# 測試方法

## 1. 自動化測試（不需要資料庫）

```bash
mvn test
```

預期：全部模組 BUILD SUCCESS，共 194 個測試。
- 未設定測試資料庫時，`JdbcUserDaoTest`（3）、`JdbcBankDaoTest`（4）、`JdbcPracticeDaoTest`（5）略過；設定方式見 [DATABASE.md](DATABASE.md) 第 5 節。
- 專案根目錄沒有 `tessdata/` 時，`ExtractionServiceTest` 中 2 個實際 OCR 的測試略過，見 [OCR.md](OCR.md)。
- 資料庫與語言資料都具備時，194 個全部通過。

## 2. 打包

```bash
mvn -q package
```

產生 `server/target/server-0.1.0-SNAPSHOT.jar`、`client/target/client-0.1.0-SNAPSHOT.jar`、`tools/target/tools-0.1.0-SNAPSHOT.jar`。
伺服器執行中時 jar 會被鎖住，重新打包前請先關閉伺服器。

## 3. 手動測試：第二階段（登入與房間，主控台客戶端）

先依 [DATABASE.md](DATABASE.md) 確認 MariaDB 已設定，再開四個終端機視窗。

```bash
java -jar server/target/server-0.1.0-SNAPSHOT.jar
```

```bash
java -cp client/target/client-0.1.0-SNAPSHOT.jar com.exambattle.client.ClientMain
```

（第二、三、四個視窗都執行上面的主控台客戶端，分別當作 Alice、Bob、Carol。第三階段起 `java -jar` 會開啟 GUI，見第 4 節。）

| 步驟 | 操作 | 預期結果 |
|---|---|---|
| 1 | 三人各自 `/register alice Alice`（bob、carol 同理），輸入密碼 | 「註冊成功」；密碼輸入時不顯示 |
| 2 | 用錯誤密碼 `/login alice` | `! 錯誤 [INVALID_CREDENTIALS] 帳號或密碼錯誤` |
| 3 | 三人用正確密碼登入 | 「登入成功」，列出目前在線者；其他人看到「上線了」；提示列變成 `[大廳] >` |
| 4 | 在另一個視窗再登入 alice | `ALREADY_LOGGED_IN` |
| 5 | Alice `/create` | 顯示 6 碼房間代碼，Alice 標示【房主】；提示列變成 `[房間 XXXXXX] >` |
| 6 | Bob `/join` + 代碼（小寫也可以） | Bob 看到 2 名玩家；Alice 看到「Bob 加入了房間」 |
| 7 | Bob 輸入 `/room` | 列出房間玩家與房主 |
| 8 | Bob 在房內聊天 | 只有 Alice 和 Bob 看到；Carol 看不到 |
| 9 | Carol 在大廳聊天 | Alice 和 Bob 看不到 |
| 10 | `/join ZZZZZZ` | `ROOM_NOT_FOUND` |
| 11 | Bob `/leave` 後再 `/join` | Alice 看到「Bob 離開了房間」，之後又看到「Bob 加入了房間」 |
| 12 | Alice（房主）`/leave` | Bob 看到「房間已解散（房主離開），你已回到大廳」；代碼失效 |
| 13 | 房主直接關閉視窗 | 房內玩家看到「房間已解散（房主斷線）」 |
| 14 | 關閉並重新啟動伺服器，再用 alice 登入 | 可以登入，表示帳號已存入資料庫 |

## 4. 手動測試：第三階段（JavaFX 客戶端與題庫）

先啟動伺服器，再開兩個 GUI 客戶端（可以在同一台電腦開兩個視窗）：

```bash
java -jar server/target/server-0.1.0-SNAPSHOT.jar
```

```bash
java -jar client/target/client-0.1.0-SNAPSHOT.jar
```

在 JDK 24 以上執行時，主控台會出現 `Unsupported JavaFX configuration` 與 `sun.misc.Unsafe` 警告，不影響使用（見 DECISIONS.md D-017）。

| 步驟 | 操作 | 預期結果 |
|---|---|---|
| 1 | 視窗 A 按「註冊新帳號…」建立 teacher，視窗 B 建立 student，各自登入 | 進入主視窗；上方顯示名稱與「目前位置：大廳」；大廳列出另一人 |
| 2 | 大廳聊天互傳訊息 | 兩人都看到，時間由伺服器決定 |
| 3 | A 按「建立房間」 | 自動切到「房間」分頁，顯示 6 碼代碼，A 標示【房主】（你） |
| 4 | B 在大廳輸入代碼（小寫也可）按「加入房間」 | B 切到房間分頁；兩人的玩家列表都有兩人；房內聊天只有房內看得到 |
| 5 | A 按「離開房間」並確認 | B 看到「房間已解散（房主離開）」並回到大廳 |
| 6 | A 到「題庫」分頁 | 左側有 8 個初始分類與「（全部）」 |
| 7 | A 選「數學」→「新增考卷」：名稱、年份 2024、類型「期中考」 | 考卷出現在清單中，建立者為 A |
| 8 | 選取該考卷 →「新增題目」：單選題 4 個選項、點選正確答案、填解說 | 題目出現在右側清單；下方預覽以 ✔ 標示正確答案 |
| 9 | 新增多選題（勾兩個正確答案）與是非題（選「對」） | 題數變成 3，「未設答案」為空 |
| 10 | 新增一題單選題但不選正確答案，按確定 | 跳出「尚未設定正確答案，仍要儲存嗎？」；儲存後清單標示「⚠ 答案未設定」，考卷的「未設答案」為 1 |
| 11 | 單選題勾兩個正確答案、選項留空、只填一個選項 | 對話框提示錯誤，不會送出 |
| 12 | 選一題按「上移」「下移」「編輯」（例如改成多選）、「刪除」 | 順序、內容、題數即時更新 |
| 13 | B 到「題庫」分頁選同一份考卷 | 看得到題目與選項，但看不到正確答案；編輯、刪除、新增按鈕停用；顯示「你不是建立者」 |
| 14 | A 按「編輯考卷」改名稱與分類；再新增一個分類（例如「物理」） | 清單更新；B 按「重新整理」後看得到 |
| 15 | 關閉並重新啟動伺服器，兩人重新登入 | 考卷、題目、答案、順序都還在 |
| 16 | A 刪除考卷 | 考卷與其題目都消失 |
| 17 | 關閉伺服器 | 客戶端顯示「與伺服器的連線中斷」並回到登入畫面 |

## 5. 多客戶端同時連線測試

伺服器啟動後：

```bash
java -jar tools/target/tools-0.1.0-SNAPSHOT.jar localhost 5555 100 10 10
```

參數依序為 host、port、客戶端數、房間數、每人訊息數。每個客戶端會註冊一個 `lt_` 開頭的帳號、登入並進入房間。預期輸出：

```text
完成：100/100 個客戶端收到同房全部聊天，耗時 … ms
每個房間的人看到的順序一致：是
結果：通過
```

結束碼 0 表示通過，1 表示失敗（會列出失敗的客戶端與原因）。
由於每個帳號都要做 PBKDF2 雜湊，100 個客戶端大約需要數秒。

測試帳號會留在資料庫中，可用以下 SQL 清除：

```sql
DELETE FROM users WHERE username LIKE 'lt\_%';
```

## 6. 手動測試：第五階段（單人練習、紀錄、錯題本）

準備：用 A 帳號在題庫建立一份考卷，至少包含一題單選、一題 5 個選項的多選（例如正確答案為 A、C）、一題是非、一題未設定答案的單選。B 帳號用來練習。

| 步驟 | 操作 | 預期結果 |
|---|---|---|
| 1 | B 到「練習」分頁 | 考卷下拉選單列出考卷與「可練習題數」（未設定答案的題目不計入） |
| 2 | 完整考卷＋考試模式，按「開始」 | 只出現已設定答案的題目；上方顯示題號與經過時間 |
| 3 | 單選答對；多選只選 A（漏選 C）；是非答錯；用題號按鈕前後切換 | 已作答題號變成淺藍色，切回時答案還在 |
| 4 | 按「交卷」 | 結果：多選得 0.6 分且標示「部分給分」，總分 =（1 + 0.6 + 0）÷ 3 × 100 = 53.3；每題顯示你的答案、正確答案（✔）、解說 |
| 5 | 到「紀錄」分頁 | 個人成績與紀錄出現這一筆；雙擊開啟同樣的結果 |
| 6 | 到「錯題本」分頁 | 多選題與是非題在錯題本中，錯誤次數 1；下方顯示正確答案與解說 |
| 7 | 按「複習錯題」→ 選練習模式 →「開始」 | 只出現錯題；每題「送出答案」後立即顯示對錯與解說，該題不能再修改 |
| 8 | 全部答對後查看錯題本 | 題目仍在錯題本（只能手動移除） |
| 9 | 再做一次完整考卷且答錯 | 錯題本中的錯誤次數變成 2 |
| 10 | 選一題按「移出錯題本」並確認 | 該題消失 |
| 11 | 隨機抽題：選「（不限考卷）」、分類「數學」、題數 2 | 只抽出 2 題 |
| 12 | 練習模式作答一題後按「結束練習」 | 提醒未作答題數；結果中未作答的題目 0 分 |
| 13 | A 修改或刪除考卷後，B 開啟舊紀錄 | 紀錄內容不變（作答當時的快照）；被刪除的題目從錯題本消失 |
| 14 | A 登入查看「紀錄」 | 看不到 B 的紀錄 |
| 15 | 練習中途關閉視窗再登入 | 尚未交卷的練習不在紀錄中（已知限制） |

## 7. 手動測試：第六階段（考卷匯入）

準備三種檔案：
1. 由 Word 等軟體匯出、含題號與 (A)(B)(C)(D) 選項的 PDF（有文字層）。
2. 同一份考卷的掃描 PDF，或拍照後轉成的 PDF（只有影像）。
3. 一張考題的 JPG 或 PNG。

| 步驟 | 操作 | 預期結果 |
|---|---|---|
| 1 | 登入後切到「匯入」分頁 | 上方顯示「檔案只在這台電腦上處理，不會上傳到伺服器」 |
| 2 | 選擇有文字層的 PDF →「開始擷取」 | 幾秒內完成；頁面清單顯示「文字層」；右側列出題目草稿，選項切分正確 |
| 3 | 考卷有「單選題／多選題／是非題」分段標題時 | 草稿的推測題型跟著分段變化；是非題沒有「找不到選項」警示 |
| 4 | 選擇掃描 PDF →「開始擷取」 | 進度列逐頁前進；頁面顯示「OCR」；每頁約 3–5 秒 |
| 5 | 處理多頁 PDF 時按「取消」 | 停在目前這一頁之後，已完成的頁面保留 |
| 6 | 選擇 JPG／PNG | 以 OCR 辨識，結果同上 |
| 7 | 查看有 ⚠ 的草稿 | 草稿內容列出需要確認的原因，例如選項記號辨識不完整 |
| 8 | 所有草稿 | 「正確答案：未設定」，系統不推測答案；題庫中沒有新增任何題目 |
| 9 | 「儲存草稿…」→ 關閉程式 → 重新開啟 →「開啟草稿…」 | 頁面文字與題目草稿完全還原；用記事本打開草稿檔，只有檔名，沒有資料夾路徑 |
| 10 | 選擇 .docx 或超過 50MB 的檔案 | 顯示清楚的錯誤訊息 |
| 11 | 暫時把 `tessdata` 資料夾改名後匯入掃描檔 | 顯示「找不到 OCR 語言資料」並指向 OCR.md；有文字層的 PDF 仍可擷取 |
| 12 | 匯入時觀察伺服器的主控台 | 沒有任何與匯入相關的紀錄（檔案沒有送到伺服器） |

## 8. 手動測試：第七階段（校正、答案卷、匯入題庫）

延續第 7 節的檔案，另外準備一份答案卷（例如在記事本輸入「1.B 2.C 3.C 4.ACE 5.○」，或答案卷的圖片）。

| 步驟 | 操作 | 預期結果 |
|---|---|---|
| 1 | 擷取掃描 PDF | 左側列出題目，全部標示 ○（未設答案）或 ⚠（需修正）；右側「原始頁面」顯示該題所在頁面 |
| 2 | 點選有 ⚠ 的題目，修正題型、選項（拆開併在一起的選項）、題目文字 | 狀態即時變成 ○；紅字消失 |
| 3 | 單選題點選一個正確答案、多選題勾選多個、是非題選「對」 | 狀態變成 ✔ |
| 4 | 「匯入答案卷…」→ 貼上答案文字 | 預覽列出「題號 → 答案」；無法解析的部分以 ⚠ 列出 |
| 5 | 「從答案卷檔案擷取…」選答案卷圖片 | 文字框填入辨識文字，預覽更新；可以先修改再套用 |
| 6 | 「套用」 | 顯示套用題數、找不到的題號、未套用的原因；對應題目的答案已勾選 |
| 7 | 套用時，單選題給兩個答案（例如 1.AB） | 該題不套用，原因為「單選題卻有多個答案」 |
| 8 | 勾選一題 ⚠ 需修正的題目後按「匯入題庫…」 | 不允許匯入，並自動選取該題 |
| 9 | 修正後「匯入題庫…」→ 建立新考卷 | 有未設答案時先詢問；成功後顯示「已匯入 N 題」；題目變成 ☁ 並取消勾選 |
| 10 | 到「題庫」分頁 | 新考卷的題目、選項、正確答案、順序與校正內容一致 |
| 11 | 到「練習」分頁練習這份考卷 | 只出現已設定答案的題目，計分正確 |
| 12 | 新增一題後「匯入題庫…」→ 加到我的考卷最後 | 題目加在原考卷最後；別人的考卷不會出現在選單中 |
| 13 | 「儲存草稿…」→ 重開 →「開啟草稿…」 | 校正內容、答案、勾選與已匯入標記都還原；原始頁面需按「選擇原始檔以對照…」 |
| 14 | 開啟第六階段存的舊草稿 | 可以正常開啟並校正 |

## 9. 手動測試：題組（閱讀測驗、克漏字）

使用大考中心公布的 115 學年度學測英文試卷與參考答案 PDF（有文字層）。PDF 只在本機使用，不放進版本控制。
資料庫需先執行 `db/migrations/001_question_groups.sql`（見 DATABASE.md）。

| 步驟 | 操作 | 預期結果 |
|---|---|---|
| 1 | 「匯入」→ 選擇試卷 PDF →「開始擷取」 | 共 50 題；題目與選項中沒有「第 1 頁 請記得…」「- 1 -」「一、詞彙題」等殘留 |
| 2 | 檢查 1–10 題 | 一般單選題，4 個選項，不屬於題組 |

## 編碼注意事項

在 Windows 主控台中直接執行時，Java 會使用主控台的編碼，中文可正常輸入與顯示。
若把輸入或輸出導向管線或檔案，Java 會改用系統預設編碼（繁中 Windows 為 MS950），
此時請加上 `-Dstdin.encoding=UTF-8 -Dstdout.encoding=UTF-8`。導向輸入時密碼會以一般文字讀取。
