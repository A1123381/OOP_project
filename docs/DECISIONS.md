## D-005 通訊協定：一行一個 JSON
- 日期：2026-11-01　狀態：已確認（v0.2，第一階段實作）
- 決定：TCP Socket、UTF-8、每行一個 JSON 物件 `{type, requestId, payload}`。
  第一階段訊息：HELLO、WELCOME、PING、PONG、CHAT、CLIENT_JOINED、CLIENT_LEFT、ERROR、BYE。
- 理由：以行分隔易於用 `BufferedReader.readLine()` 處理，也方便用 telnet / nc 手動測試；
  `requestId` 讓請求與回應可以對應。
- 影響：詳見 [PROTOCOL.md](PROTOCOL.md)。v0.2 定案：埠號 5555、單行上限 65536 字元、客戶端每 15 秒 PING、伺服器 45 秒逾時，新增錯誤碼 `ALREADY_WELCOMED`。

## D-008 伺服器並行模型
- 日期：2026-11-01　狀態：已確認
- 決定：
  - 每條連線一條 virtual thread 負責讀取。
  - 每個客戶端有自己的送出佇列與寫入執行緒，`send()` 只把訊息放進佇列，不會因單一慢速客戶端阻塞廣播。
  - 加入、離開、聊天廣播都在 `ClientRegistry` 的同一把鎖內完成，所有客戶端看到的事件順序一致。
  - 時間戳（`serverTime`）由伺服器產生。
- 理由：需求 3.6 要求伺服器統一控制並同步狀態；Java 21 virtual threads 讓每連線一執行緒的寫法簡單且可擴充。
- 已知限制：送出佇列目前沒有上限，第八階段穩定性測試時再評估背壓（backpressure）。
- 影響：`server`。

## D-011 密碼雜湊
- 日期：2026-11-01　狀態：已確認
- 決定：JDK 內建 PBKDF2WithHmacSHA256，16 位元組隨機 salt，210,000 次迭代，256 位元輸出；迭代次數與 salt 一起存入資料庫，日後可調整。
  以 `MessageDigest.isEqual` 比對；帳號不存在時也做一次雜湊，避免以回應時間探測帳號。
- 理由：不需額外依賴，符合 OWASP 建議。
- 影響：`server/.../auth/`。

## D-016 資料庫改用 MariaDB
- 日期：2026-11-01　狀態：已確認（使用者選擇）
- 決定：
  - 資料庫由 MySQL 改為 **MariaDB**（本機 13.0，服務 `MariaDB`，埠號 3306）。
  - 驅動改為 `org.mariadb.jdbc:mariadb-java-client` 3.5.1，連線字串為 `jdbc:mariadb://`。
  - 加入 `org.slf4j:slf4j-jdk14`，讓驅動日誌走 java.util.logging。

- 安全：伺服器只用權限受限的 `exam_battle` 帳號，不用 root；所有密碼只存在 `config/db.properties`（不進版本控制）或環境變數，不寫進任何文件。

## D-023 單人練習的計分規則
- 日期：2026-11-01　狀態：已確認（使用者選擇多選題依學測規則）
- 決定：
  - 單選、是非：答對 1 分，否則 0 分。
  - 多選：n 個選項中有 k 個與正確答案不一致，得 max(0, (n − 2k) / n) 分；未作答 0 分。
  - 只有全對算「答對」。
  - 總分為各題得分平均 × 100，四捨五入到小數 1 位。
  - 只出已設定答案的題目。
- 答案揭曉：開始時由使用者選擇考試模式（交卷後一次批改，可前後修改）或練習模式（每題立即批改，不能修改）。
- 計分與計時由伺服器負責（`server/.../practice/Grader`），開始練習時不傳送答案。
- 本階段不設時間限制。

## D-025 進行中的練習與紀錄快照
- 日期：2026-11-01　狀態：已確認
- 決定：
  - **進行中的練習**只存在伺服器記憶體，每人同時一個，開始新的會取代舊的；斷線時清除。
  - **紀錄寫入**：交卷時在同一個交易內寫入 `practice_records`、`answer_records`，並更新 `wrong_questions`。
  - **題目快照**：每題作答保存當時的題目快照（JSON，含正確答案與解說）。題目之後被修改或刪除，歷史紀錄仍保持原樣；`answer_records.question_id` 改為 NULL。
  - **時間欄位**：一律以 UTC 寫入 `DATETIME(3)`，避免 `TIMESTAMP` 的自動更新與時區轉換。
  - **驅動限制**：MariaDB 驅動的批次協定不支援 `INSERT … SELECT … ON DUPLICATE KEY`，錯題的新增或累計改為逐筆執行。
- 已知限制：斷線或伺服器重啟時，尚未交卷的練習會遺失；之後若需要「中斷後繼續」，再把進行中的練習寫入資料庫。
- 影響：`db/schema.sql`、`server/.../dao/JdbcPracticeDao`、`server/.../practice/`。

## D-026 OCR 在客戶端本機執行，新增 `ocr` 模組
- 日期：2026-11-01　狀態：已確認（使用者選擇客戶端本機）
- 決定：
  - 新增 Maven 模組 `ocr`（`com.exambattle.ocr`），由 client 依賴。
  - 以 Apache PDFBox 3.0.3 擷取 PDF 文字層與轉影像，以 Tess4J 5.13.0（內含 Windows 版 Tesseract 5 原生檔）辨識影像。
  - PDF 逐頁處理：文字層有 20 個以上非空白字元就直接使用，否則轉成 200 DPI 影像再 OCR；使用者也可以勾選「強制 OCR」。
  - 辨識時設定 `user_defined_dpi=300`、`preserve_interword_spaces=1`，並移除中文字之間殘留的空白。
- 理由：
  - 實測在沒有解析度資訊時，Tesseract 會假設很低的 DPI，中文辨識嚴重錯誤。
  - 以 300 DPI 放大掃描影像反而比 200 DPI 差，因此 PDF 掃描頁採用 200 DPI。
- 影響：client jar 約增加至 33MB；伺服器不變。

## D-035 題組切題規則
- 日期：2026-11-02　狀態：已確認
- 背景：以 115 學年度學測英文試卷實測，舊的切題規則把文章併進前一題的選項，文意選填、篇章結構一題都切不出來。
- 決定：`QuestionSplitter` 改為多步驟處理，輸出 `SplitResult {groups, questions}`。仍然只用格式比對，不使用 AI、不推測答案：
  1. **頁首頁尾**：移除在一半以上頁面的頁首／頁尾區（前後各 3 行）重複出現的行（數字視為相同、不計字詞順序），以及 `- 1 -`、`第 1 頁`、`共 11 頁` 等頁碼行。
  2. **大題標題與說明**：`一、詞彙題（占 10 分）`、`第壹部分`（容許字間空白）、`說明：…`（含換行的續行）不併入題目，並用來推測題型。`混合題`、`非選擇題`、填充、簡答、作文、翻譯段落的題目標成「不支援」，匯入時預設不勾選。
  3. **題組標題**：`第 11 至 15 題為題組`、`第11-15題為題組`、`請閱讀下文，回答第 1 至 3 題`、`Questions 1-3`。標題到第一題之間的文字是題組文章；題組內只接受範圍內的題號，避免文章中的數字被當成題號。
  4. **三種題組**：
     - 閱讀測驗：每題有題幹與選項，照常切題。
     - 克漏字：題號後面直接是選項，題幹填入「第 11 格」。
     - 共用選項（文意選填、篇章結構）：範圍內的題號都沒有出現，文章後面是一組 `(A)…` 選項；依範圍逐題產生，題幹為「第 21 格」，每題複製同一組選項。
  5. **空格標記**：只在克漏字與共用選項題組，把前後有兩個以上空白、底線或括號的範圍內題號改成 `【11】`。範圍內有題號找不到空格時加上警示。閱讀測驗的文章不處理，避免改到年份或數量。
  6. 範圍內找不到的題目產生空白題目並警示；沒有標題但超過 200 字的無題號文字，暫時視為下一題的題組文章並警示。
  7. 選項的文字跨越過多行（例如地圖、圖表）時警示「選項可能是圖片或圖表」。
  8. 文章的行依「上一行以句號結束且明顯比最長的行短」判斷換段；中文行之間不加空白。
- 驗收：115 學測英文 50 題全部切出，7 個題組範圍正確，47–50 標為非選擇題。
- 測試使用自製的同結構文字，不把考試中心的試題放進版本控制；實際 PDF 只在本機驗證，根目錄的 `*.pdf` 已加入 `.gitignore`。

## D-036 答案卷的獨立記號與非選擇題

## D-037 多人競賽規則（第四階段）
- 日期：2026-11-02　狀態：已確認（使用者選擇）
- 決定：
  - **參賽者**：房間內所有人（含房主）都是玩家。競賽中不能加入房間、不能移出玩家；離開的玩家不再出現在排行榜上。

- 實作：伺服器 `game` 套件（`GameManager`、`Game`、`GameScoring`、`GameTiming`）。競賽狀態與房間共用同一把鎖；計時由單一排程執行緒觸發；資料庫存取（選題、寫入錯題）都在鎖外。測試時以 `GameTiming` 縮短時間。
- 協定 v0.8：`START_GAME`、`GAME_STARTED`、`GAME_QUESTION`、`SUBMIT_ANSWER`、`ANSWER_ACCEPTED`、`GAME_PROGRESS`、`QUESTION_RESULT`、`GAME_OVER`、`END_GAME`。

## D-044 圖片的上傳與取得（協定 v0.10）
- 日期：2026-11-05　狀態：已確認（使用者選擇「自動縮小，每張最多 1 MB」「選檔案＋貼上剪貼簿」「題庫編輯也要」）
- 決定：
  - `UPLOAD_IMAGE {mime, data(Base64)}` → `IMAGE_SAVED {imageId, width, height}`。伺服器檢查檔頭確實是 PNG／JPEG 且與 `mime` 相符、≤ 1 MB、寬高各 ≤ 4000 像素，否則回 `IMAGE_INVALID`。
  - `GET_IMAGE {imageId}` → `IMAGE {imageId, mime, data}`。**知道 id 就能取圖**：圖片不是答案，id 隨機、無法猜測，且只出現在看得到的題目資料中；這樣競賽玩家不需要另外的權限就看得到房主私人考卷的圖。
  - 題目、選項、題組引用的 id 必須存在，否則 `IMAGE_NOT_FOUND`。
  - 客戶端在上傳前把圖片縮到寬度 ≤ 1600 像素；先存 PNG，超過 1 MB 改 JPEG 並逐步降低品質，必要時再縮小。
  - 單行上限由 1,048,576 調高為 2,097,152 字元（1 MB 圖片的 Base64 約 1.4M 字元）。
  - 匯入校正時圖片只在本機（草稿 v4 以 Base64 保存）。按「匯入題庫」時先逐張上傳再送 `IMPORT_QUESTIONS`；每次都重新上傳本機圖片，因為草稿中記得的 id 可能已被清除，而相同內容會拿回同一個 id。
  - 競賽出題時客戶端立即取圖；圖片未載入時顯示「圖片載入中…」，倒數照常進行。

## D-045 自動截取圖片選項
- 日期：2026-11-05　狀態：已確認（使用者選擇「人工框選＋自動截圖」）
- 決定：
  - **只在選項看起來不是文字時觸發**：選項行數多於 選項數×2＋2，或有選項是空白。此時清空選項文字（原本的零碎文字不保留），並警示「選項可能是圖片或圖表：已清空選項文字並自動截圖，請對照原始頁面確認」。正常的文字選項不會被換成圖。
  - 定位：文字層 PDF 用 PDFBox 的每字座標；掃描檔用 Tesseract 逐字位置框。先找到題號，再依序找 (A)(B)… 記號，依縱座標分列。
  - 每個選項的範圍：從它的記號到同一列下一個記號（或右邊界），往下到下一列、下一題題號或頁面下緣（94%）。以 0–1 相對座標表示，從 200 DPI 的頁面圖截取，再去掉四周空白。
  - 有一列的高度太小（看起來是文字選項）就不截圖。截不到時留給使用者框選或自備圖片。
  - 題幹圖與題組文章圖的位置難以只靠格式判斷，不自動截取，只提供人工框選與自備圖片。
  - 自動截圖只是草稿，一律可以重新框選、換圖或移除。
